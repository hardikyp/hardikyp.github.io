# Performance Baseline

This directory contains the repeatable measurement setup for `P0-A1`.

The baseline is split into two layers:

1. Static baseline:
   Generated by `scripts/perf_baseline.py`.
   This works without a browser and records:
   - local request count
   - external request count
   - total local bytes
   - CSS bytes
   - JS bytes
   - font bytes
   - image bytes
   - data bytes
   - partial bytes
   - runtime data requests discovered from loaded JS

2. Browser baseline:
   Generated by the GitHub Actions Lighthouse workflow.
   This captures:
   - LCP
   - TBT
   - CLS
   - performance score
   - transfer size
   - request count as seen by Lighthouse

## Why there are two reports

This repository intentionally avoids a heavy local toolchain. The static report is always available and cheap to run. Lighthouse adds browser-realistic metrics but requires Chrome, so that part runs most reliably in CI.

## Included baseline scope

The baseline currently covers these representative pages:

- home: `index.html`
- projects: `projects/index.html`
- updates: `updates/index.html`
- photography: `photography/index.html`

## Local usage

Generate the static baseline:

```bash
python3 scripts/perf_baseline.py \
  --root . \
  --json-out docs/performance/baseline-static.json \
  --md-out docs/performance/baseline-static.md
```

Optional: if Chrome is available locally, start a local server and run Lighthouse manually:

```bash
python3 -m http.server 4173
```

Then in another terminal:

```bash
npx --yes lighthouse http://127.0.0.1:4173/ \
  --preset=desktop \
  --only-categories=performance \
  --output=json \
  --output-path=reports/performance/lighthouse/home.json
```

Repeat for:

- `http://127.0.0.1:4173/projects/index.html`
- `http://127.0.0.1:4173/updates/index.html`
- `http://127.0.0.1:4173/photography/index.html`

Summarize those JSON outputs:

```bash
python3 scripts/summarize_lighthouse.py \
  --input-dir reports/performance/lighthouse \
  --output reports/performance/lighthouse-summary.md
```

## CI usage

Use the `Performance Baseline` GitHub Actions workflow.

It does three things:

1. Starts a local static server.
2. Generates the static baseline report.
3. Runs Lighthouse on the key pages and uploads the resulting reports as an artifact.

## Interpretation notes

- The static baseline is best for repo-to-repo comparisons after code changes.
- Lighthouse is best for browser-observed rendering metrics.
- The static baseline does not execute JS, so it should not be treated as a full substitute for Lighthouse.
- When comparing results over time, compare like-for-like:
  - same workflow
  - same page set
  - same desktop/mobile preset
